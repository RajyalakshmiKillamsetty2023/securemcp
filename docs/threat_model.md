# Threat model

## 1. System under protection
An LLM agent receives a user query and a set of N tools, each with a name and a natural-language
description. The agent picks one tool and its arguments. SecureMCP sits between the agent's choice
and execution and returns ALLOW, FLAG or BLOCK.

## 2. Attacker
**Controls:** the name and description text of one or more tools in the offered set.

**Does not control:** the user query, the agent LLM and its prompt, the gateway code and
thresholds, other tools' descriptions, the tool implementations.

**Goal:** hijack the choice, so the agent selects the attacker's tool when a legitimate tool is the
correct one for the query.

**Success:** the agent selects the malicious tool and the gateway returns ALLOW.

### Attacker knowledge levels
| Level | Knowledge | Used in |
|---|---|---|
| A0 Non-adaptive | None. Uses a fixed attack family | E2, E3 |
| A1 Adaptive, black-box | Can query the detector and see its decision or score; rewrites for 3 rounds | E6 |

White-box attackers (access to detector weights or gradients) are out of scope.

## 3. Attack families (malicious class)
| Family | Idea |
|---|---|
| Explicit instruction | Description tells the agent to use this tool |
| Preference manipulation | Description claims to be best, fastest or preferred |
| Name collision | Tool name mimics a legitimate tool |
| Conflicting instruction | Description contradicts or overrides other tools |
| Irrelevant instruction | Description carries instructions unrelated to the tool's function |
| Obfuscated wording | Same intent as above, disguised (paraphrase, odd formatting, encoding-like text) |

## 4. Benign classes
- **Normal:** plain functional descriptions (from BFCL).
- **Promotional (honest):** marketing-style wording that describes a real tool truthfully. These must
  not be blocked. Measuring false alarms here is a core part of the study.

## 5. Out of scope
- Prompt injection in tool outputs or retrieved content
- Compromised servers, rug-pull updates after approval, multi-turn attacks
- Argument-level attacks after the correct tool is chosen
- White-box and gradient-based attacks on the detector
- Real tools, real networks, real credentials

## 6. Sandbox rules
- All tools are fake functions returning canned data.
- No file-system, network or credential access from any tool.
- Attack data is text only; it is never executed.
- The LLM runs on Colab or via a hosted API, never with tool access beyond the fake tools.

## 7. Assumptions and limits
- The agent is one 7-8B instruct model; results may not transfer to larger or hosted models.
- Attacks are generated by an LLM and rewriting loops, not harvested from live servers.
- The gateway sees only text and the model's choice (black box), not model internals.
